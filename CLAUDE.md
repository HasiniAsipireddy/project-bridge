# Project: Innovator-Student Bridge

Two-sided platform connecting innovators (who post project ideas) with students
(who browse and request to join). Innovators create projects; students send join
requests; innovators accept or reject them.

## Stack

| Layer | |
|---|---|
| Client | Vite 8 + React 19, react-router-dom 7 (`client/`) |
| Server | Express 5, ESM (`"type": "module"`) (`server/`) |
| Database | PostgreSQL on **Neon**, Prisma 6 |
| Auth | JWT in an httpOnly cookie, bcrypt (cost 12) |
| Validation | zod 4 (server-side, via `validateBody`) |
| Lint | oxlint (client only) |

Planned, not built: AWS S3 (resumes, portfolio files, avatars), AWS SES (request
notifications), deployment target undecided.

## Dev commands

```bash
# server -> http://localhost:4000
cd server && npm run dev        # node --watch src/index.js

# client -> http://localhost:5173
cd client && npm run dev        # vite
```

- Vite proxies `/api/*` to `localhost:4000`, so the browser sees one origin and
  the session cookie is same-site in dev.
- Client `apiFetch` uses `VITE_API_URL` if set, else the relative `/api`.
- Other scripts: `npm run build` / `lint` / `preview` (client),
  `npm start` / `prisma:generate` / `prisma:studio` (server).

## Data model

`server/prisma/schema.prisma`. All ids are `uuid()` strings generated by Prisma
(no DB-level default).

**Enums**
- `Role` — `innovator` | `student`
- `RequestStatus` — `pending` | `accepted` | `rejected`

**User** — `id`, `email` (unique), `name`, `password_hash`, `role`, timestamps
- `projects` (as owner), `requests` (as student)

**Project** — `id`, `title`, `description`, `tech_stack` (Postgres `text[]`),
`owner_id`, timestamps
- `tech_stack` is non-nullable and defaults to `[]`; "at least one entry" is
  enforced in zod, **not** the DB
- Index on `owner_id`

**Request** — `id`, `student_id`, `project_id`, `status`, `message?`, timestamps
- `@@unique([student_id, project_id])` — a student can hold only **one** request
  per project. Routes let the DB enforce it and translate Prisma `P2002` into a
  409; that's the only race-free place to check.
- Indexes on `project_id`, `student_id`

All three FKs are `ON DELETE CASCADE` — deleting a project clears its requests;
deleting a user clears their projects and requests.

Migrations applied: `20260910025012_init`, `20260910155550_add_tech_stack`.

## Neon connection setup

Two URLs in `server/.env`, both pointing at the same database:

- **`DATABASE_URL`** — the **pooled** endpoint (host contains `-pooler`). Used by
  the running app.
- **`DIRECT_URL`** — the **direct** endpoint (same string, `-pooler` removed).
  Used only by `prisma migrate`.

Both are wired in the `datasource` block (`url` and `directUrl`), so the Prisma
CLI routes migrate commands to `DIRECT_URL` automatically:

```bash
cd server && npm run prisma:migrate -- --name <migration_name>
```

**Why:** the pooler is PgBouncer, which breaks the advisory locks
`prisma migrate` takes. Running migrations through it hangs or fails, and can
leave migration state inconsistent. **Never point migrate at the pooled URL.**

## Auth flow

- Register/login hash or verify with bcrypt, then set a `token` cookie:
  `httpOnly`, `sameSite: 'lax'`, `secure` in production, lifetime derived from
  the JWT's own `exp` claim.
- JWT payload is **only** `{ sub, role }` — nothing that can go stale.
- `cookieParser()` runs before the routers; without it `requireAuth` cannot read
  an httpOnly cookie.
- **`requireAuth`** (`middleware/requireAuth.js`) — verifies the cookie, sets
  `req.user = { id, role }`, else 401.
- **`requireRole('innovator' | 'student')`** (`middleware/requireRole.js`) —
  403 on mismatch. Mount **after** `requireAuth`.
- Role alone is never sufficient for mutations: every project/request write also
  checks ownership and 403s otherwise.
- `GET /api/auth/me` returns `{ id, name, email, role }` — read from the DB, not
  echoed from the token, so profile edits show up without re-issuing the cookie.
- Login compares against a dummy hash for unknown emails so response timing
  doesn't reveal which addresses are registered.

## Routing quirk

`requestsRouter` is mounted at **`/api`**, not `/api/projects`, because its paths
span three prefixes (`/projects/:id/requests`, `/requests/:id`, `/my-requests`).

`projectsRouter` mounts first and only defines `/` and `/:id` (a single segment),
so `/api/projects/:id/requests` **falls through** to `requestsRouter`. Mount
order in `app.js` matters — keep `projectsRouter` before the `/api` mount.

## API routes

| Method | Path | Auth | Purpose |
|---|---|---|---|
| POST | `/api/auth/register` | public | Create account, set cookie, 409 on duplicate email |
| POST | `/api/auth/login` | public | Verify credentials, set cookie |
| POST | `/api/auth/logout` | public | Clear the cookie (204) |
| GET | `/api/auth/me` | auth | Current user `{id, name, email, role}` |
| GET | `/api/projects` | public | All projects, newest first, with owner `{id, name}` |
| GET | `/api/projects/:id` | public | One project + owner + `request_count` |
| POST | `/api/projects` | innovator | Create; owner is `req.user.id` |
| PATCH | `/api/projects/:id` | innovator + owner | Partial update; empty body 400s |
| DELETE | `/api/projects/:id` | innovator + owner | Delete (requests cascade) |
| POST | `/api/projects/:id/requests` | student | Ask to join; 409 if already requested |
| GET | `/api/projects/:id/requests` | innovator + owner | Incoming requests + student info |
| PATCH | `/api/requests/:id` | innovator + owner | Set status `accepted` \| `rejected` |
| GET | `/api/my-requests` | student | Own requests + project + project owner |

Notes:
- `PATCH /api/requests/:id` rejects `pending` — a decision isn't undone by
  reverting to the initial state.
- Non-owner access returns 403, missing rows 404, validation failures 400 with
  `{ error, fields, form? }` (`form` carries whole-body `.refine()` errors).
- No payload ever includes `password_hash`.

## Folder conventions

**Server** (`server/src/`)
- `routes/` — one router per resource; handlers live inline, no controllers layer
- `middleware/` — `requireAuth`, `requireRole`, `validate` (`validateBody`), `errorHandler`
- `lib/` — `prisma.js` (singleton client), `token.js` (sign/verify + cookie helpers)
- `config/env.js` — all env access; `required()` fails fast at boot
- `app.js` builds the app, `index.js` listens and handles shutdown

**Client** (`client/src/`)
- `pages/` — one per route
- `components/` — shared UI (`Nav`, `ProtectedRoute`)
- `context/AuthContext.jsx` — `AuthProvider` only (component-only file, or Vite
  fast refresh breaks)
- `hooks/` — `useAuth` (holds the context object too), `useApi` (loading/error/data)
- `lib/api.js` — `apiFetch`; throws on non-2xx with `.status` and `.body` attached
- `styles.css` — app styles. `App.css` is the original template CSS; leave it alone.

## Notes for Claude Code

- **Plan before coding.** Prefer Plan Mode for anything touching more than one file.
- **Ask before adding dependencies** not already in the relevant `package.json`.
- **One resource/feature at a time**, tested end to end before moving on.
- **Migrations always target `DIRECT_URL`**, never the pooled `DATABASE_URL`. The
  `datasource` block handles this — don't override it.
- **Never commit real `.env` values.** `.env` is ignored at the root *and* in
  `server/`; only `.env.example` is tracked, with placeholders.
- Use `async`/`await`, not `.then()` chains.
- Validate every request body with zod through `validateBody` before the handler.
- Keep commits small — one feature per commit, on a branch, fast-forwarded into
  `main`.
- Don't modify `client/src/App.css`.
